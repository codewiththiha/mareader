## 0.1.2

### One runtime per pane

- Every document pane is created in its own frame, with its own WASM module, its
  own document and its own engine session. A PDF beside a Markdown file no
  longer shares a reactive owner, a raster budget or a module instance, so work
  in one pane cannot stall the other and a fault in one stays in one.
- Realms are disposable, not recycled. There is no warm frame kept behind a
  route, no pre-warm on hover, no in-place document swap: returning to the shelf
  tears the reader down, and opening a book again builds a fresh frame from what
  is stored on disk. That costs a boot and buys the absence of a stale one.
- The handoff between the window and a pane is authenticated on every message —
  generation, nonce, role. A frame that has been removed cannot answer for a
  living one, and a late reply cannot reach a host that is already gone, which
  is the class of bug that used to surface as a document opening in the wrong
  pane after a fast close-and-reopen.

### A look per pane

- Two independent switches: **independent themes** gives each pane a colour of
  its own, **independent textures** gives each pane a page pattern of its own.
  A look a pane owns is a whole look, so the colour switch carries the pattern
  with it; `shared base` narrows only the base mode inside colour.
- Picks are random but deliberately unlike what is already on screen: the hue
  is taken from the middle of the widest gap between the hues showing, and a
  pattern is chosen among the modes nobody is wearing. Two panes never open as
  near-copies of each other.
- A mode exists to serve a split. With one pane placed it stands down, and as
  the split collapses the last pane's look is **promoted to the window**, so the
  surviving pane and the chrome agree instead of disagreeing about what the
  reader looks like. Switching a mode off by hand folds only that family back.
- Both switches are in the appearance menu — each row appears with the split it
  serves — and in Settings → Workspace. Film grain stays a window dial: it is
  the window's own surface, not a pane's paper.

### Textures on every format

- Real paper, lined, grid, dotted and cross work per pane for PDF, Markdown and
  plain text. A PDF page carries the pattern on the page; a reflow pane carries
  it on the scroller, so the pattern scales with the zoom and stays put while
  the text scrolls under it. Opacity and pitch are dials, per pane.
- A lined PDF can sit beside a plain Markdown page because each pane reads its
  own look, not the window's. A pane that owns nothing shows the window's
  pattern, so there is one source of truth and no second sync path to fall out
  of step.
- Four fixes from re-reading the whole change: switching colour off no longer
  erases the patterns the other panes were wearing; a split that the tree
  refused to place no longer leaves a phantom pane look behind forever; each
  switch now seeds its own family from the live window rather than from the
  composed look a pane was showing, so a fold cannot resurrect a theme you
  already dropped; and the texture switch finally has a Settings row beside its
  colour sibling instead of living only in a menu that needs a split.

### Memory that is counted, not promised

- Everything an open document allocates is counted on its create edge and its
  dispose edge, and the pairs must balance: sessions, workers, renders,
  prefetches, virtualizers, panes, listeners, observers, timers. A double
  dispose now fails the build instead of reading as a quiet zero.
- Closing a pane releases its engine and worker, zeroes its canvas backing
  stores (removing the DOM does not free a canvas), drops its thumbnail cells,
  and clears the timers that were keeping its frame chain alive.
- Evicted list rows are bridged rather than dropped: a strip keeps a row mounted
  for a bounded grace measured in wall-clock *or* frames, whichever its owner
  uses, and the frame chain stops itself when nothing is owed a tick.
- The whole window shares one two-slot full-page raster budget, with per-owner
  permits, because a full-page raster is main-thread work: four panes
  re-theming at once pace as one progressive sweep instead of stacking four
  stalls on a page you are reading. Removing a reader reclaims every
  descendant's permits, even the ones still arriving.

### Reader behaviour

- The thumbnail rail is now honest about its cost: each card is its own small
  raster instead of a shrunk page, the lane is throttled, the cache is a bounded
  LRU, prefetch runs only when the reader is idle, and a look change re-bakes
  just the visible cells from their stored raw bitmap.
- A zoom commit is one raster per mounted page rather than four, and the anchor
  re-lands after the measurement settles, so a zoom at 3x does not queue a
  hundred canvases to paint the same page.
- A slider scrub touches the pane you are dragging: only that pane's sessions
  re-raster, the others stay painted, and the settled rasters are baked while
  the live ones are filtered.
- Search, selection, gloss cards, drag and drop, tabs, split axes, zoom and
  virtualization keep the behaviour they had, now asserted per pane rather than
  per window.

### For people who build it

- `node tools/dev.mjs` builds and serves the optimized artifact set the app
  actually ships, and CI measures that same `dist` — one canonical build for
  development, the native smoke test and the memory replay.
- Two gates. `CI` runs format, lint, tests, the web contracts and the macOS
  shell on every push that touches code; `Deep CI` boots the real app in a real
  browser and in the native window and replays a split read in Chromium and
  WebKit. The expensive lane now has a written rule: it runs for anything that
  allocates, retains, counts or releases, and a change that is only
  presentation can mark itself `[skip deep]` — nightly takes no notice of the
  mark, so nothing stays skipped.
- The docs describe the tree: `docs/architecture.md`, `docs/pane-runtimes.md`,
  `docs/runtime-split.md`, `docs/session-ownership.md`,
  `docs/lifecycle-ownership.md`, `docs/memory-baseline.md`, `docs/memory/`,
  `docs/ci-architecture.md` and `docs/frame-lifecycle-alternatives.md`. The
  review records that used to accumulate beside them are gone; the rules they
  stated moved to where a change would meet them.
