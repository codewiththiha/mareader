## 0.2.0

### Under the hood

- The reader's surface — state, virtualizers, zoom, reading effects and the reading components —
  moved into a `reader-app` crate behind a one-directional edge: the shell calls the reader, never
  the reverse. The window still mounts a single wasm binary; nothing about opening, reading,
  zooming or searching changed.
- Shell-owned types went home: sidebar/motion enums to `reader-core`, cover plumbing to
  `library-core`, the invoke types to `ai-core`, and the chrome primitives (plus the shared event
  table) to a new `ui-kit` crate. The shell controller now builds from signals in `app-chrome`.
- The Phase-2 seam is declared but unused: `reader-core::wire` names the events a second window
  would speak, so splitting the build target later is mechanical, not exploratory.
