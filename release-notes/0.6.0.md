## 0.6.0

### View modes and zoom

- The reader now has four view modes instead of one: **Single** (one page at a
  time), **Spread** (two pages side by side, gapless, paginated like a book),
  **Scroll Vertical** (every page in one continuous strip) and **Scroll
  Horizontal** (the same strip, sideways). Paging, scrolling, jump-to-page and
  search all work the same way in each mode.
- Zoom, fit-to-width and fit-to-page were folded into one pipeline that drives
  all four modes. The continuous and horizontal virtualizers are kept in
  lockstep during a zoom or a fit change, so a spread never re-centers
  halfway through a resize, and search hits reveal on whichever axis is
  active.
- Auto-scroll runs only in the two scrolling modes, at a fixed speed, and
  switches itself off at the end of the document.
- Fit, zoom, the page indicator, spread gap, page margins, blend scope and
  the sidebar's overlay behaviour all live in one layout section of settings
  and persist between launches, so the reader comes back shaped the way you
  left it. The last document stays on the shelf and resumes at its saved page.

### Reader chrome

- The reader gives up its title bar and toolbar row for the page. The toolbar
  is an overlay that hides after the pointer leaves it and returns from the
  full-width band at the top of the window; while a popover, menu or the search
  field is open the bar pins itself open instead of vanishing under the cursor.
  Everything the old bar carried — open/library, the document title, and the
  mode, zoom and appearance controls — lives there.
- The document title is centered with a compact view menu for modes, zoom,
  fit and auto-scroll, and the page number moved to a corner pill
  (`94 / 198`) that stays out of the way of the text.
- Page navigation and a scroll slider for the continuous modes live in a
  hover-reveal bar at the bottom of the reader.
- The sidebar leads with a chrome row that *is* the title bar while it is
  open, followed by the book's identity (cover, title, author, and the file
  path on hover). Thumbnail and outline toggles moved to an icons-only rail at
  its foot; the active panel gets a filled chip, and clicking the icon you are
  already on jumps to where you are rather than resetting the panel.

### Gloss word-cards

- Selecting a word can ask the configured AI provider about it: the answer
  streams into a card anchored to the selection, which can be dragged,
  collapsed back to its mark, and reopened from the mark itself. A right-click
  on a selection opens the same action set, and explained words stay marked in
  the page so a card can be recalled later without re-selecting.

### Search

- Full-text search moved out of JavaScript and into the wasm module: the engine
  hands pages over once, and matching, snippet windows and result ordering run
  against the Rust index with no per-query round trip. The index builds three
  pages per turn with a yield between turns, so a textbook-sized document neither
  floods the pdf.js worker nor blocks the main thread. Results for ASCII
  documents are byte-identical to the previous matcher.

### Window chrome on Windows and Linux

- Both now run frameless: the native title bar is replaced by a minimize /
  maximize-restore / close cluster at the far edge of the toolbar row, so the
  caption buttons hide and return with the rest of the chrome instead of
  floating over the page. Double-clicking the bar still maximizes, and the
  maximize glyph follows the window's real state — Win+arrow snapping,
  drag-to-edge and taskbar restores included — rather than the clicks the app
  happened to see. macOS keeps its native traffic lights and is unchanged.
- Windows and Linux no longer reserve space for traffic lights that do not
  exist, so the toolbar and the sidebar header start at their resting padding
  instead of an empty gutter.

### Performance

- The theme bake (the filter and paper blend that produces dark and dim pages)
  runs in a worker off a DOM-free filter kernel shared with the main thread,
  with a lookup-table memo and a permanent inline fallback if workers are
  unavailable. Appearance slider scrubs keep their live per-frame preview.
- The continuous reader's virtualization kernel was rewritten around
  sub-pixel-exact integer extents with a neighbour-first lookup, so smooth
  scrolling resolves the visible page range in amortized constant time, and
  sub-epsilon wheel jitter no longer wakes page tracking or the retention
  pass. Zombie retention now runs on a monotonic clock, so a wall-clock jump
  cannot expire the mounted page cache in one go.
- Page rendering overlaps text extraction, outline destinations resolve
  concurrently through a bounded pipeline, the canvas pool refuses oversized
  retentions, and a burst of page turns collapses into the one raster for the
  page you land on.

### Stability and presentation

- The output device pixel ratio cap went from 1.25 to 2 and the viewport-pixel
  budget that used to throttle it below native was dropped: small text is
  visibly sharper on high-DPI screens, and the render read-ahead grew so
  scrolling no longer shows a dark flash ahead of the newly mounted pages.
- Sidebar thumbnails transition immediately and within a bounded queue, and a
  cell whose render was cancelled or evicted from the cache mid-flight now
  heals itself instead of staying blank.
- Dead code and duplicate implementations were pruned across the workspace —
  one windowing implementation, one shared Tauri event subscription helper, one
  table of the frontend/engine event names — and the remaining lint surface was
  cleared under `-D warnings`, so new slop fails the build.
- Windows and Linux release builds were broken: a misfiled Trunk key asked it
  to download a binaryen release named after an optimization level, which is a
  404 before any bundle is produced. The size pass itself is unaffected — the
  level is still requested where Trunk reads it, on the rust link in
  `index.html`.
