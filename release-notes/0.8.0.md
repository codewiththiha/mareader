## 0.8.0

### The library

- The shelf is a library now, not a list of what you opened last. You make a shelf, name it, file
  books into it and file a shelf inside a shelf. The breadcrumb is the chain you are standing on,
  and a chain deeper than the bar is wide folds behind three dots rather than scrolling off it.
- The bar keeps its own memory: the columns you asked for, the sort, the view. A knob that only
  paints the shelf is on the bar; a knob that changes what the library holds is on a sheet.
- A folder's card is a plate of the covers inside it, so a folder reads as the tree it holds
  rather than as a rectangle with a name on it. Covers that fail to arrive are retried by the
  library itself, and a plate whose books have not rendered yet says it is waiting rather than
  showing four grey squares.

### Watched folders

- Import a folder and the library watches it. A rescan reconciles what is on disk with what is on
  the shelf: books that arrived are shelved, books that left are marked, and a folder nothing
  changed in leaves no trace beyond its own "last scanned" stamp.
- The folder keeps a ledger. It remembers what it placed and what it was told to ignore, which is
  what makes re-importing safe: a book you removed last week is not handed back to you by a
  rescan, because the ledger still says you removed it.
- A removal is remembered as a tombstone, and a tombstone is an offer. The folder's restore menu
  reads its own log and can put a book back — in the name the shelf showed, on the shelf it stood
  on. A book that comes back is lit rather than announced: the import succeeded by making it
  reappear where the folder holds it, and a highlight says that without a sentence.
- A book you move back into the folder by hand is recognised as the book you removed, not imported
  beside it as a second copy.
- Importing a folder again also brings back the books its shelf stopped holding: one you filed
  onto a shelf of your own, and one whose shelf you took apart, are each a file the walk still
  finds and the library still holds, so each was a *nothing new* to the rescan's table — and a
  re-import that reported nothing while the folder you picked was missing books read as a broken
  import. They come back onto the rung their own directory names, as a second membership rather
  than a move, so the shelf you carried a book to keeps it. Only a walk with nothing to give back
  says so.
- Importing a watched folder again brings back the book you took out of it, which is what importing
  it again means. It used to depend on a race: picking a folder hands the window its focus back, and
  the focus walk got there first and refused the import you asked for. An import now waits out a
  rescan of the same folder instead of losing to one. Picking a NESTED folder of the tree again is
  the same reconciliation: the tree's walk runs, the book you removed inside the nested folder
  comes back, and the rung you picked lights up — instead of a sentence that only pointed at it.
- Watching is a decision per SUBFOLDER, and it has a door on every shelf: right-click any shelf of
  a folder the library reads in place — its own, any rung of its tree, or one you made inside it —
  to watch that ground for new books or to stop. From the root shelf the row turns the whole tree,
  and from a rung it turns that subfolder alone, with the tree above keeping its own answer; the
  row says which ground it is about, and the dot a folder card draws is the same per-rung answer
  the row turns. A rescan adds files only under the rungs that are watched, and an import you ask
  for by name still imports what it finds — the watch is about the walks nobody asked for. The
  import sheet's switch speaks the same vocabulary: on a folder the library already reads it opens
  showing the state that tree is in and answers for the subfolder being imported, and what it
  shows is what lands — it used to lock on covered ground, and a lock the reader could not move
  was a switch that did not work.

### Read in place, or copy

- A folder can be read where it lies, or copied into the library's own storage. Read in place and
  the shelf points at your files; copy and the library owns the bytes, so a file that moves or is
  deleted elsewhere cannot take a book off your shelf.
- A folder that was read in place can be re-picked as copies later, and the copies ask only the
  level's own name question — a copies import is the library's second instance, unrelated to any
  tree: **show it** lights the shelf that is here and imports nothing, **replace** sends its
  books out and seats the copies on it, and **as new** mints the counter-named shelf whose books
  are copies of their own — independent books, with their own marks and their own place —
  because a second instance you asked for by name is not the same book as the first. And ground
  a read-at-place tree still reads is no obstacle to a copies import: a nested folder picked
  with the switch off while the outer tree stands used to answer with a silent "Imported 0
  books"; every file the library reads in place now becomes a book of its own on the copies
  shelf, beside the linked book the tree keeps.
- A loose file you drop on the library lands as the library's own copy. There is no folder to
  read in place, and a single file the library does not own is a book that can vanish.
- A copied book is named after the file it came from, everywhere the library shows a name — the
  shelf, the search, the reader's title bar, the log a removal leaves. The copy's own file inside
  the store is called `source.pdf`, which is the layout's word for the book and not the reader's,
  and no surface reads it as a name any more.
- Moving a read-in-place book off the shelf its folder filed it on makes it the library's own
  copy — including a move to another shelf of that same folder. What ties the book to the folder
  is the ground its file stands on, not the folder's shelves, so the folder's log stays free and
  importing that file again brings the linked book home to the shelf it belongs on and lights it
  up there. Re-ordering the books on the shelf they are already on copies nothing.
- A shelf a folder reads in place now acts the way its books do. Taking it off the seat its
  folder's tree names asks first — the sheet counts the books the move will copy and names the
  copy it will leave behind — and on the answer the shelf and every read-in-place book on it
  become the library's own copies, under the next free name, while the folder on disk keeps
  standing. The copy is bound to nothing: no rescan, no import and no light ever answers through
  it. Import that folder again and its shelves come back where the disk has them, with the books
  in their old names; cancel and nothing moved at all. A shelf of a folder the library copies
  still moves without a word, the way a stored book does.
- A move inside the shelf's own family never has to cost a copy. Dropping a read-in-place shelf
  on a rung of a tree its directory belongs to offers **put it back in its place** beside the
  copy and the cancel: a folder you once imported on its own folds back into the family tree, on
  the rung its directory names, and a shelf an older build left off its seat reseats. Importing
  a folder answers the same way without being asked — a folder whose rung the family lost comes
  back inside the family, and a folder found standing outside its tree goes home on the next
  import of that tree, with a note naming the shelf that went back.
- A folder import lights the FOLDER: you stay on the level that holds it and its card lights up,
  the way a file import lights the file's book. Drilling inside a folder you just imported to
  light one book in it reported the contents as the content.
- A copy the library makes is a file of its own, and measures as one: it takes its own
  modification time rather than the source's, which is what leaves the source file's identity
  free for the folder that reads it. On the hosts whose copy carries the source's stamp across,
  a book you moved out of a folder used to come back as a second copy beside the first instead of
  as the link on its own shelf; libraries already in that state are read back correctly, and the
  book comes home to the shelf it left.
- A folder you imported on its own, whose directory is inside a tree the library also reads, goes
  back to that tree on the next import of either — the outer tree's walk, or a pick of the
  member's own directory, which folds it onto the rung the directory names. The note that rises
  is the report of the shelf that went home, with the folder's ledger folded into the tree's, so
  nothing it removed comes back on the next rescan.

- A right-click now hands you out of the library and into the OS: **Reveal in folder** opens the
  file manager on the item itself — the library's stored copy for a book it copied, the file
  where it stands for a book read at its place, the target for a link, and the directory its
  tree cut it from for a watched folder's shelf. A shelf you made yourself has no directory and
  gets no row.
- A right-click also makes a second instance: **Duplicate** copies the thing under the pointer —
  a book read at its place becomes a second file beside the first, in the file manager's counter
  name (`dune_1.pdf`, and duplicating a duplicate steps rather than stacks), and a book the
  library copied becomes a second copy in its store. The duplicate is a row of its own — its own
  name on the level's counter, its own progress and highlights — filed right behind the row you
  pointed at, on every shelf the original is on. A link duplicates as a link, and the selection's
  menu duplicates the set, one report for the batch.
- A shelf duplicates too, from the same right-click and from the crumb's own menu: a second shelf
  of yours holding the same books, with the whole tree inside it copied along, in the level's
  counter name and right behind the shelf it came from. It costs no disk, because a shelf holds
  membership and never held a byte — the books are the same books on two shelves. A watched
  folder's shelf copies as one of YOURS rather than as a second shelf of the folder: one directory
  is one linked shelf, and a second one would be two doors to it with only one on the ledger, so
  the copy answers to no rescan, no fold and no departure.
- A right-click also renames: **Rename…** opens one field seeded with the name the thing shows,
  Enter commits and Escape leaves it alone. It is the name the LIBRARY shows and nothing else —
  the file a book reads keeps the name it has on disk, the row keeps its id, its place in the
  book, its highlights and every shelf it is on. A link renames its own name and a shelf its
  shelf, from the same row of the same menu, and the crumb's inline field renames the shelf you
  are standing on through the same service. A name you type survives as typed: the rule that
  drops a title shaped like a filename hunts the debris a document's own metadata carries, and a
  name a person chose is not debris whatever it looks like.

### One book, one row

- Identity is the file's content, not its address. The same PDF opened twice, dropped twice or
  imported from two folders is one book on the shelf, and the second arrival is filed beside the
  first rather than duplicated.
- A link is the exception, and it is explicit: one file can be two books when you ask for two, and
  the second is a book of its own — its own marks, its own place, its own progress. The library
  remembers which books are independent, so a rescan does not fold them back into one.
- A duplicate is the same kind of exception: the copy wears its own measurement, so a folder that
  holds both files holds two books to every walk rather than one book twice — and removing the
  duplicate is a removal the folder's rescan honours, not a book that walks back in.
- A book a folder read in place that is later copied keeps its place on the shelf. The conversion
  happens under the row, not beside it.

### Importing

- The folder sheet asks before it walks: whether the folder is new, continues one you have, or
  replaces it — and, for a folder that is already here, whether the tree it found is its own,
  merged into the shelf that stands, or a replacement for it.
- A merge asks per file wherever two names meet. A file whose name a standing shelf already holds
  gets the three answers — one book, replace, or as new — one at a time or one answer for all of
  them. Files nothing collides with join silently, because a new book in a merged folder is the
  default and not a case.
- A planned tree holds every book the folder has, not only the new ones: the files the library
  already held are filed into the tree as memberships of the rows it holds them in, so a
  re-import of a folder whose every file is known still produces the tree you asked for.
- Dropping a file on the library lands it on the level you dropped it on, and the import sheet
  unfolds the path it is about to import so you can see what will be made before it is.

### Removal is a receipt

- Removing says what left, and offers it back. A shelf removed with books inside it is taken
  apart in the receipt, so what you get back is the set that actually went rather than a number.
- A book that leaves a watched folder leaves as the library's own copy, so removing it from the
  shelf does not delete the file you imported it from — and the folder's log knows the way back.
- Removing a book the library COPIED deletes the copy and the folder it lived in: every stored
  book owns one folder under the id that never changes, so a removed book leaves no empty
  directory behind for a sweep that does not exist to find.
- Cancelling a collision sheet drops the question on screen and every one waiting behind it,
  which is what a file manager's copy dialog has always meant by Cancel: the placements already
  answered keep their answers, and the ones not asked simply do not land.

### Search the shelf

- The library's search answers as it is typed, fuzzy, ranked, with suggestions under the bar. A
  title that is a filename is not treated as a title, and a query that matches nothing says so
  rather than showing an empty grid.
- The search rule and its panel are one rule: what the suggestion list ranks is what the shelf
  filters on, so an answer you can see in the panel is an answer you can reach from it.

### Drag, hold and the set

- Hold a book to select it, and act on the set. A press decides once what it meant — a hold, a
  drag or a click — so the three cannot race and a finger cannot both select and drag the same
  press.
- A drag out of a branch lifts the branch, not the page, and a rest folds a set into a shelf.
  Every shelf row has the shelf's whole gesture, and every list row a target and a container, so
  a drop lands where the edges say it will.
- The shelf's drag is the app's own, not the browser's: no drag image from the compositor, no
  half-rendered ghost, and a drop that is a library decision rather than a file-manager one.

### Under the hood

- `library-core` holds the rules and nothing else: identity, shelves, the rescan ledger, the
  collision's three answers and the filename arithmetic. It is a crate with no platform in it, so
  every rule in this release is a rule a test can call — `cargo test -p library-core` runs them on
  the host, with no browser, no shell and no filesystem.
- The library's surfaces read their facts back by id rather than by carrying them, so a card, a
  row and a menu cannot disagree about the book they are all showing.
- A persisted library is validated on load and the validation is idempotent: a shelf whose member
  names no book drops the member, a folder shelf goes with its folder, and two rows sharing an id
  leave one book and one member.
- The reader's settings modal rides the same shell every other sheet rides, so one dialog in the
  app cannot have a different escape key, a different backdrop or a different heading from the
  rest.
