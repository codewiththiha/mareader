## 0.7.0

### Text and Markdown documents

- `.txt` and `.md` files are documents now, not attachments: they open from the dialog, the
  shelf, a drag onto the window or a file association, and they get the same reader — view modes,
  zoom, search, outline, thumbnails, appearance, progress and the AI gloss.
- Markdown is rendered, not displayed: headings, lists, tables, blockquotes, rules, links and
  fenced code blocks, with GitHub-flavoured tables and task lists. Links open in a new tab. Raw
  HTML in a Markdown file is refused — these are your own files, but a document is still untrusted
  input, and a reading view has no use for an inline `<script>`.
- An image is the exception: it displays when its source is a `data:` URI, and not when it points
  at a file or a URL. The reader admits no network origin, and its asset protocol serves documents
  rather than the images beside them.
- Front matter is read for the title and author, so a Markdown file shelves under its own name
  rather than its filename.

### Type instead of pixels

- A text document is parsed into blocks, and the blocks are packed onto pages by measuring real
  type: a hidden column laid out with the same width, font and scale reports each block's height,
  and the cutter packs pages from those numbers. Nothing is rasterized, so text stays selectable,
  searchable and sharp at every zoom, and zooming never re-paginates.
- Move a typography knob and the pages re-cut, but the reader keeps the block you were on rather
  than the page number you were on — which is the same idea the continuous modes already had.
- Paragraphs taller than a page are split at line boundaries, and a continuation carries no
  paragraph space of its own, so a paragraph broken across a cut still reads as one paragraph.
- In vertical mode a text document is not paginated at all: it streams as one **continuous
  column** with no page breaks, virtualized block by block, so a long book costs no more than a
  short one.

### Fonts

- A new Fonts tab holds the type: a default family plus separate serif, sans and mono picks,
  size, weight, line spacing, paragraph margin, word and letter spacing, first-line indent, full
  justification, hyphenation, and the column alignment the continuous stream uses.
- A book layout replaces the symmetric page margins with an inner gutter at the spine. Which
  side the gutter falls on alternates with the page's parity, exactly like a bound book, and a
  spread fixes it per hand: left-hand page, right-hand page.

### Appearance for text

- Text pages have their own paper. The base mode, the tint, the texture modes and the film grain
  all apply, but they recolour type through tokens instead of filtering a bitmap: a text page is
  never pushed through the PDF's colour machine, and blend mode — which mixes ink into a page
  raster — stays a PDF feature and is not offered while a text document is open. The Theme tab
  hides the Paper and Rendering sections accordingly.
- Body ink has its own comfort dial, **Text ink intensity**, which mixes the theme's ink toward
  its paper.
- The texture modes tile across the text scrollers as well, and follow the same opacity dial.

### The AI gloss in any format

- Selection, the Explain pill, the word card and the saved highlights now ask a format-agnostic
  question. Every page host publishes which family painted it and which page it shows, and every
  rendered block publishes its index, so the feature finds the words by attribute rather than by
  a `.pdf-page` selector.
- A highlight in a reflowable document remembers the **block and the character range** inside its
  rendered text, not a rectangle in page space: a font change, a resize, a column flip or a
  re-parse all re-cut the pages, and a mark that stored pixels would point at whatever moved
  underneath. Marks whose block cannot be found right now are hidden rather than drawn somewhere
  approximate.
- For Markdown the offsets count the rendered text, which is why a heading's highlight survives
  its `#`s not being on screen.
- The pill is called **Explain** everywhere; "Info" described the button, not what it does.

### Search, outline and progress

- Text search runs in-process over the blocks — the document is its own index, so there is no
  engine round trip — and hits are mapped through the current page cut.
- Those hits are now painted over the type with the same boxes a PDF gets: the same tint, the
  same amber current match, the same wrap-around stepping, and one box per line fragment when a
  hit wraps. Stepping to a result scrolls to the block the hit sits in rather than to the top of
  its page.
- Both families now scan with the same code and quote the same window. A result's snippet shows
  32 characters either side of the hit whichever format it came from — a PDF's used to show 25
  before and 30 after, a text document's 48 and 48, and the list then cut both to 80 — and a PDF
  query is trimmed of surrounding spaces before matching, as a text query already was.
- Markdown headings become the sidebar's chapter tree, republished on every re-cut, so the
  outline follows a font change instead of going stale.
- Progress in the continuous column saves the fractional stream position beside the page, so a
  long read resumes where it stopped rather than at a page top.

### Paint and motion

- A zoom no longer flashes. The snapshot that covers the transition is tagged with the theme
  generation it was painted under, so a commit that lands under a different theme discards it:
  the white flash at the end of a zoom in a dark theme, and the dark or hue-shifted frame in
  sepia, green and the textured themes, are both the same stale-snapshot bug and both are gone.
- Thumbnails no longer flare neon while they re-render: the skeleton's pulse is held for the
  duration of a theme crossfade instead of restarting under it.
- The hidden measure column no longer paints on a cold load, where it was visible for a frame
  before the first layout pass moved it off-screen.
- The loading mark runs off the main thread — compositor-driven transform and opacity — so it
  keeps turning while a large document is being parsed. It is also the one motion exempt from the
  animation switches: a frozen spinner cannot be told apart from a hung app, so under either net
  it trades its travel for a fade and keeps going.

### Under the hood

- The workspace split along formats: `reader-core` holds the format-agnostic domain (settings,
  appearance models, zoom maths, the format registry), `reflow-core` the shared maths of
  reflowable text, `txt-core` and `md-core` one parser each, `ui-geom` the pure geometry of the
  floating panels, `tauri-bridge` the window externs declared once for every frontend crate, and
  `app-chrome` the format-agnostic window chrome. `pdf-core` keeps what is actually about PDFs.
- The frontend follows the same line: `components/viewer` is shape, `components/formats` is
  substance, and a page host joins them — so a format adds pages without editing the layouts.
- The selection tracker moved into its own small bundle that loads first and needs no pdf.js,
  which is what lets a text document have a selection at all.
- The DOM walk that turns a block's characters into pixels is one module both overlay painters
  now share (`formats/reflow/spot.rs`): a gloss mark's stroke projection and the search-hit layer
  ask it the same question, so they cannot disagree about where a word is — and the layers a walk
  must skip (a stroke's button, a hit's box, the measure column's twins) are one list. The
  invalidation fingerprints those overlays refresh on moved beside the layouts they describe,
  into `viewer/refresh.rs`.
- Finding a query's occurrences was three scanners — the PDF index's, the text pipeline's and the
  highlight painter's — with three case-folding rules and three offset units, and the ordinals
  they produce are exactly what a painted box and a results-list row meet on. It is now one
  (`reader_core::search::occurrence_spans`), with the snippet window beside it, and all three
  callers use it. Two of the three also read their offsets out of a lowercased copy of the text,
  which is wrong whenever folding changes a string's length; the shared scan refuses to guess in
  that case and falls back to a case-sensitive read of the text the reader sees.
- Dead weight out: a `cached` flag the thumbnail cell stopped reading when it began probing the
  cache synchronously (removed in Rust and in the engine, along with two comments that still
  called it load-bearing), two byte offsets on a text hit that only the old snippet cutter used,
  a hover signal no consumer subscribed to, and a `ReaderState` context nothing read.
- Settings sections now live with the feature they configure, the shelf and the marks each have
  one writer, and the three frame loops read the clock once per frame between them.
- Five consistency gates joined CI: the version in its four files, the openable formats in the
  three lists that must agree, the module and component names the documents and comments refer
  to, the event names the engine dispatches, and the DOM contract the engine reads and the app
  writes. Each fails the build rather than warning.
