## 0.5.0

### Library

- A "recent books" shelf replaces the bare open prompt: every opened PDF is
  remembered with its last-reached page, so reopening resumes where you left
  off. Covers are rendered from the first page; books can be removed from the
  shelf; the list is capped at 20 and persisted separately from appearance
  settings.

### Reading

- Copy/paste and drag-selection now follow visual reading order: out-of-order
  font runs (italics, bold, list numbers, caption labels) are reordered at
  layer-build time, so pasted text is no longer scrambled and a single drag
  paints one contiguous highlight.
- Selection is scoped to the glyph spans: dragging over blank space, margins,
  or the gap between pages can no longer re-anchor the selection to the top of
  the page or paint the whole-page tint wash.
- Fixed a hang where reopening a scrolled document could stall on "Opening…".

### Interface

- A themed drag-and-drop overlay appears while a file is dragged over the
  window (following the active base mode and tint), and the sidebar toggle is
  hidden on the home screen where there is nothing to show.

### Performance

- The theme (canvas filter + paper blend) is now baked into each page and
  thumbnail raster once per render instead of running as live CSS on the
  compositor. Every page is a single opaque texture rather than a texture
  plus a filter intermediate plus a blend group, which is what let the
  webview's GPU process outgrow the renderer process in memory — most
  visibly while scrolling, zooming, and sliding the sidebar. Colours are
  byte-identical and the render scale / DPI budget is unchanged, so text
  stays exactly as sharp. Appearance slider scrubs keep their live per-frame
  page preview through a temporary fallback to the CSS pipeline.
- Fixed Dark mode not darkening the page: the baked filter ran through the
  2D canvas `filter` property, which Chromium silently ignores on
  software-rasterised canvases (the Windows WebView2 flags request software
  raster) and WebKit did not support before Safari 18 — Dark's `invert()`
  never ran, leaving the page white, while Dim still darkened through its
  blend. The bake now captures the filter through the same element-level CSS
  `filter` path the live pipeline always used, so Dark works on every
  engine, GPU or software raster alike.
- Theme changes no longer re-bake the whole thumbnail cache: cached
  thumbnails are stamped with the theme generation and re-bake lazily on
  next use, so switching appearance only re-bakes the pages and cells on
  screen.
- Page render starts are coalesced by one frame, so a burst of thumbnail
  jumps or page turns collapses into a single render for the page you land
  on instead of a queue of cancelled raster jobs (this also fixes the
  Windows-only freeze after a few rapid thumbnail jumps to distant pages).
- Virtualization pre-render cut across the board: the continuous view keeps
  half a screenful of read-ahead (was a full screenful) and at most 5
  mounted pages (was 7), the thumbnail grid keeps 1 buffer row (was 2), and
  the thumbnail bitmap cache holds 48 pages (was 64). Same look and feel;
  fewer off-screen rasters mounted at any moment. The thumbnail placeholder
  still covers the gap while a page mounts, so fast scrolling stays
  visually smooth.
- On Windows the WebView2 rasterization of UI chrome is moved off the GPU
  (compositing stays hardware-accelerated), cutting GPU memory further
  without affecting page rendering or text sharpness.

### Opening files

- Double-clicking a PDF, using "Open with", or setting the app as the
  default PDF handler now opens that file directly (and resumes at the saved
  page); launching the app with a file while it is already running forwards
  the file to the open window.
- PDFs are read through the native backend instead of the asset-protocol
  HTTP fetch, which fixes the Windows-only "could not open PDF" failure on
  the first reopen after launch.
